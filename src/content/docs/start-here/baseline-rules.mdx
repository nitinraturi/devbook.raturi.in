Some rules must apply to every change in every project: design principles, coding standards, security, testing and the definition of done. They should not depend on an assistant deciding a page looks relevant. Devbook ships them as short **rule packs**. A sync tool installs the packs where each assistant loads them automatically, and CI fails when they go missing or drift.

## What this can and cannot guarantee

No instruction file can force a model to obey. Anthropic describes `CLAUDE.md` as context, not enforced configuration. GitHub notes Copilot "may not always follow your custom instructions". Devbook therefore guarantees what is deterministic and backs the rest with checks.

| Layer | Guarantee | Mechanism |
|---|---|---|
| Selection | The baseline is always chosen | `core` is forced on; platform profiles come from `devbook.json`, not from the agent |
| Loading | The rules are in context, not behind a link | Native always-loaded files for Claude and Copilot |
| Integrity | The rules match the pinned Devbook version | `devbook-sync.mjs --check` in CI fails on missing, edited or stale files |
| Compliance | Violations are caught before merge | Project lint, type, test, accessibility and audit checks required by the definition of done, plus human and Copilot code review |

Treat the fourth layer as the real enforcement. If a rule matters and a tool can check it, add the check to the project's CI.

## Profiles

`core` applies to every project. Add the profiles that match the product:

| Profile | Use when | Covers |
|---|---|---|
| `core` | Always | Workflow, design principles, coding standards, security, dependencies, testing, Git, definition of done |
| `web` | The project serves HTML or a web UI | Design system, WCAG 2.2 AA, performance budgets, technical SEO, security headers |
| `mobile` | Native, React Native, Flutter or similar apps | Platform conventions, accessibility settings, offline, permissions, secure storage, store policy, releases |
| `llm-features` | The product calls a language model at runtime | Prompts as code, untrusted model output, tools, RAG, budgets, AI disclosure |

Each pack stays at 150 lines or fewer, because long instruction files lower adherence. Each pack links to the full guide pages for detail.

## How each assistant loads them

The sync tool copies the packs into the project instead of linking to them. Copilot's cloud agent and code review read the project's own files, and a link inside an instruction file is only a reference the model may not follow.

- **Claude Code** loads `.claude/rules/devbook-*.md` at launch in every session, because the files have no `paths` frontmatter. `CLAUDE.md` contains `@AGENTS.md`, so project rules are expanded into context at launch too.
- **Copilot in VS Code** attaches `.github/instructions/devbook-*.instructions.md` to every request that reads or changes a file, because the files declare `applyTo: "**"`.
- **Copilot cloud agent and code review on GitHub** read the same `.github/instructions/` files and `AGENTS.md` for each task and each review.
- **Other agents** read `AGENTS.md`, which tells them to read `.claude/rules/devbook-*.md` before their first change. Loading depends on the agent and is not guaranteed.

Confirm loading in Claude Code with `/context`, which lists the loaded memory and rule files. In VS Code, the references list under a Copilot response shows which instruction files were attached.

## Install and check

Run from the project root after adding the [pinned submodule](/start-here/adopt-in-a-project/). Node 18 or later is needed, but no packages are installed.

```bash
# Install core + web (core is always added)
node docs/devbook/bin/devbook-sync.mjs --profiles web

# Re-sync after bumping the Devbook pin; reads profiles from devbook.json
node docs/devbook/bin/devbook-sync.mjs

# CI: exit 1 if a pack is missing, hand-edited, stale or not configured
node docs/devbook/bin/devbook-sync.mjs --check
```

The tool writes `devbook.json`, `.claude/rules/devbook-<profile>.md` and `.github/instructions/devbook-<profile>.instructions.md`. Commit all of them. Removing a profile from `--profiles` deletes its generated files.

## Stronger enforcement (optional)

- **Required status checks.** Branch protection makes the drift check and the project's own checks block merge.
- **Copilot code review.** It reviews pull requests against the same `.github/instructions/` files.
- **Claude Code hooks.** A `Stop` or `PreToolUse` hook in `.claude/settings.json` can run the project's lint and tests, or block edits to generated rule files. Hooks run shell commands, so review them like code.

## Rules

- A project **MUST** install the baseline with `devbook-sync.mjs`. It **MUST NOT** paste or paraphrase rule packs by hand.
- `core` **MUST** always be installed. Platform profiles **MUST** match the product, recorded in `devbook.json`.
- Generated rule files **MUST NOT** be edited. Record tightened rules or deviations in `AGENTS.md`. Loosening a security, privacy, accessibility, testing or content-honesty rule also needs an [ADR](/templates/adr/), following the [precedence rules](/start-here/introduction/#precedence).
- Project CI **MUST** run `devbook-sync.mjs --check` with submodules checked out, as a required check.
- After bumping the Devbook pin, the project **MUST** re-run the sync in the same pull request.
- In Devbook, a change to a guide page's rules **MUST** update the matching pack in `rules/` in the same change.
