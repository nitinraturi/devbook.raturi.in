The [setup prompt](/#setup) does all of this for you. The steps below show the same setup done by hand. New to instruction files? Read [How Devbook works](/start-here/how-it-works/) first.

**You need:** a git repository, and an assistant that reads `AGENTS.md` or `CLAUDE.md`, such as Claude Code or GitHub Copilot in agent mode, with file editing and terminal access turned on.

## 1. Choose how to add Devbook

Both methods put the latest release, from `main`, in `.devbook/`, so the rest of the setup is the same. `.devbook/VERSION` holds its version number, such as `2026.11.02.1`, and Devbook changes in your project only when you update. Pick a tab.

<Tabs syncKey="method">
<TabItem label="Submodule (tracks updates)">

Adds Devbook as a submodule that tracks `main`. You update with one command, and every update shows up as a reviewable change.

```sh
git submodule add -b main https://github.com/nitinraturi/devbook.raturi.in .devbook && git add .devbook
```

</TabItem>
<TabItem label="Copy (plain files)">

Downloads the latest release as plain files that you commit. It works offline afterwards, needs no submodule support from tools or cloud agents, and only changes when you download again.

```sh
P=devbook.raturi.in-main && rm -rf .devbook && mkdir -p .devbook && curl -fsSL https://codeload.github.com/nitinraturi/devbook.raturi.in/tar.gz/main | tar -xz --strip-components=1 -C .devbook $P/instructions $P/stacks $P/templates $P/skills $P/kit $P/LICENSE-CC-BY-4.0 $P/VERSION $P/CHANGELOG.md $P/devbook.manifest.json
```

On Windows PowerShell, which has no `rm -rf` or `mkdir -p`, use the `curl.exe` and `tar.exe` that ship with Windows 10 and later:

```powershell
$p = "devbook.raturi.in-main"; Remove-Item -Recurse -Force .devbook -ErrorAction SilentlyContinue; New-Item -ItemType Directory -Path .devbook | Out-Null; curl.exe -fsSL "https://codeload.github.com/nitinraturi/devbook.raturi.in/tar.gz/main" -o devbook.tar.gz; tar.exe -xzf devbook.tar.gz --strip-components=1 -C .devbook "$p/instructions" "$p/stacks" "$p/templates" "$p/skills" "$p/kit" "$p/LICENSE-CC-BY-4.0" "$p/VERSION" "$p/CHANGELOG.md" "$p/devbook.manifest.json"; Remove-Item devbook.tar.gz
```

Without a terminal, download the [ZIP of `main`](https://github.com/nitinraturi/devbook.raturi.in/archive/refs/heads/main.zip). Copy its `instructions/`, `stacks/`, `templates/`, `skills/` and `kit/` folders and its `LICENSE-CC-BY-4.0`, `VERSION`, `CHANGELOG.md` and `devbook.manifest.json` files into `.devbook/`.

</TabItem>
</Tabs>

## 2. Connect your assistants

<Steps>

1. Create `AGENTS.md` at the repository root and fill in the Project section with your real commands, layout and rules. In the Devbook section, keep the three `@` lines and only the "read" lines that apply: see [the table of when to load each file](/start-here/how-it-works/#mandatory-and-optional-files), plus one stack note for each technology you use.

   <Code code={agentsTemplate} lang="md" title="AGENTS.md" />

2. Create `CLAUDE.md` containing one line:

   ```md
   @AGENTS.md
   ```

3. Create `.github/copilot-instructions.md`:

   <Code code={copilotTemplate} lang="md" title=".github/copilot-instructions.md" />

4. Link the path-scoped files you chose and the skills that fit. The script reads the files your `AGENTS.md` lists, links each path-scoped one into `.claude/rules/` and `.github/instructions/` (so Claude Code and Copilot load it only for matching files), and links the matching skills into `.claude/skills/`. Where symlinks don't work, it copies the files instead. Then check the result:

   ```sh
   node .devbook/skills/devbook-setup/scripts/link.mjs
   node .devbook/skills/devbook-setup/scripts/verify.mjs
   ```

   For other assistants, add them to the list: `--assistants claude,copilot,cursor,codex`. `cursor` generates `.cursor/rules/*.mdc`, `codex` links skills into `.agents/skills/`, and `copilot-review` writes copies Copilot code review can read. Pass the same list to `verify.mjs`, and note it on the `Assistants` line in `AGENTS.md`.

5. Add the secret-file patterns to `.gitignore` (SEC-29):

   ```sh
   node .devbook/skills/devbook-setup/scripts/gitignore-secrets.mjs
   ```

6. Commit `.devbook` (plus `.gitmodules` for a submodule), `AGENTS.md`, `CLAUDE.md`, `.github/copilot-instructions.md`, `.claude/rules/`, `.claude/skills/` and `.github/instructions/`, then start a new chat.

</Steps>

## Which assistants load the rules

A load probe asks a question only Devbook answers (CORE-02, and DES-04 after opening a `.css` file), so a pass shows the files reached the assistant. It is the `astro-load-probe` eval task.

| Assistant | What setup writes | Load probe |
|---|---|---|
| Claude Code | `CLAUDE.md`, `.claude/rules/`, `.claude/skills/` | Modelled pass; not yet measured |
| GitHub Copilot (VS Code, CLI, cloud agent) | `.github/copilot-instructions.md`, `.github/instructions/`, skills in `.claude/skills/` | Not yet tested |
| Cursor | `.cursor/rules/devbook-*.mdc`, skills in `.claude/skills/` | Not yet tested |
| Codex | `AGENTS.md`, skills in `.agents/skills/` | Not yet tested |

"Modelled" means the evals worked out, from each tool's documented loading rules, that the rules are in context; see [the evals](https://github.com/nitinraturi/devbook.raturi.in/tree/main/evals). Measured results replace these as they are run.

## 3. Optional: add the enforcement kit

Instructions are context, so an assistant can still miss a rule. The kit in `.devbook/kit/` turns a few of them into checks that tools run. The setup prompt asks before installing any part, and you can add it later:

- **Claude Code hooks** that block `git push`, `.env` edits and recursive `rm` outside the project, and say when a newer Devbook release is out.
- **Git hooks** that scan staged changes for secrets with gitleaks and check commit messages.
- **Starter CI** for GitHub Actions, for Node.js or Python, with every action pinned to a commit SHA.

[Use the enforcement kit](/start-here/enforcement-kit/) has the install steps, what a block looks like and the limits. The kit is MIT-0, so you can copy and change it without credit.

## How the instructions load

Core, security and testing load in every chat through the `@` lines; Claude Code expands them, and Copilot, Codex and Cursor are asked to open them. The path-scoped files load when a matching file is read or edited (Claude Code) or edited (Copilot), and every assistant can open the files in the "read" list when a task calls for them. Skills load only their name and description until a task needs them. [How Devbook works](/start-here/how-it-works/#how-each-assistant-loads-the-rules) explains each assistant and which rule wins.

To load everything in every chat instead, for example in a short-lived project where cost doesn't matter, replace the "read" lines with `@` lines (`@.devbook/instructions/design.md`) and skip the links. Write `@` paths as plain text, because an `@` path inside backticks is not imported.

<Aside type="caution" title="Symlinks, cloud agents and submodules">
On Windows, symlinks need Developer Mode and `git config core.symlinks true`; without them, skip steps 4 and 5 and rely on the "read" lines. Hosted agents only see a submodule's files if their checkout includes submodules. If an agent says the files are missing, add `git submodule update --init` to its setup steps. For the Copilot coding agent, those steps live in `.github/workflows/copilot-setup-steps.yml`. You can also switch to the Copy method, whose files are in the repository itself.
</Aside>

## Update, clone or remove

Before you update, read the [changelog](https://github.com/nitinraturi/devbook.raturi.in/blob/main/CHANGELOG.md) entries added since your version, or run `node .devbook/skills/devbook-upgrade/scripts/compare.mjs`, which lists them. Entries with an **Upgrade** note need a change in your project, such as a new line in `AGENTS.md` or a new link.

<Tabs syncKey="method">
<TabItem label="Submodule (tracks updates)">

```sh
cat .devbook/VERSION                                                                       # the version you use
curl -fsSL https://raw.githubusercontent.com/nitinraturi/devbook.raturi.in/main/VERSION    # the newest release
git -C .devbook fetch origin main                                                          # fetch the latest release
git -C .devbook diff HEAD FETCH_HEAD -- CHANGELOG.md                                       # what changed since yours
git -C .devbook checkout -q FETCH_HEAD && git add .devbook                                 # update, then commit
git clone --recurse-submodules <your-repo>                                                 # clone a project that uses Devbook
git submodule update --init                                                                # fetch .devbook in an existing clone
git rm .devbook                                                                            # remove; then delete the Devbook section and links
```

</TabItem>
<TabItem label="Copy (plain files)">

`.devbook/VERSION` shows the version you use. Run the download command again, then review `git diff .devbook` and commit. The command replaces the whole folder, so files removed upstream are removed in your copy too. To remove Devbook, delete `.devbook/`, the Devbook section of `AGENTS.md` and the `devbook-*` links in `.claude/` and `.github/instructions/`.

To switch from Copy to Submodule, delete `.devbook/`, commit the deletion, then run the submodule command.

</TabItem>
</Tabs>

Either way, your repository records exactly which Devbook text it uses, so an update is a normal reviewable change. Review it before you commit: these files steer your assistant, so treat an update like a dependency upgrade. If a new version doesn't suit your project yet, don't commit the update.
