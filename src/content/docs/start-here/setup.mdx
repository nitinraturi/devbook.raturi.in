## Run the prompt

1. Open your coding agent in the repository: Claude Code, Codex, Cursor, GitHub Copilot agent mode, Gemini CLI or another agent that can run commands.
2. Paste the prompt below.
3. The agent reads your repository and runs your commands once, without changing anything. Then it shows a plan: the files it would write, the skills it would install with their pinned versions, and the hooks.
4. Answer "yes", or edit the plan.
5. Review the diff it reports, commit it yourself, and start a new session so the agent loads the new `AGENTS.md`.

If a teammate uses Claude Code, they run the `claude plugin install … --scope project` lines from the report once. Committing `.claude/settings.json` turns a plugin on for everyone, but it doesn't download the plugin to their machine.

## What each agent loads

| Agent | Reads the Devbook block from | Skills go in |
|---|---|---|
| Claude Code | `CLAUDE.md`, which starts with `@AGENTS.md` | `.claude/skills/`, or plugins |
| Codex | `AGENTS.md` | `.agents/skills/` |
| Cursor | `AGENTS.md` | `.agents/skills/` |
| GitHub Copilot | `AGENTS.md` | `.agents/skills/` |
| Gemini CLI | `AGENTS.md`, listed in `context.fileName` in `.gemini/settings.json` | `.agents/skills/` |

Claude Code cloud sessions don't load plugins that a repository's `.claude/settings.json` turns on, so they get the core block but not the plugins.

## Update

Paste the same prompt again. When `devbook.lock.json` exists, the prompt runs in Update mode: it compares your pinned sources and your core block with the current version, shows what would change with each source's changelog, and applies only what you approve. Your lines outside the markers stay as they are.

## Move from the old .devbook/ install

Before November 2026, Devbook was a git submodule or a copied folder at `.devbook/`, with rule files linked into each assistant. Those files no longer exist on `main`: if you update the submodule, its `@` imports and links point at nothing, and hooks that ran from `.devbook/kit/` report errors. Move before you update it, or right after:

1. Paste the bootstrap prompt into your agent.
2. Its Update mode lists everything from the old install: the `@.devbook/...` lines, the `devbook-*` links in `.claude/rules/`, `.claude/skills/`, `.github/instructions/`, `.cursor/rules/` and `.agents/skills/`, hooks that run from `.devbook/kit/`, and the submodule or folder.
3. Approve, and it removes them and writes the new block. Your Project section becomes "Project rules", and any Workflow, Analytics or Rules lines stay as your own rules.

Rule IDs such as `CORE-02` or `SEC-05` are gone. If your own rules turned one off ("ignore DES-12"), delete that line.

## Remove Devbook

Delete the block between `<!-- BEGIN:devbook-core -->` and `<!-- END:devbook-core -->` in `AGENTS.md`, the `@AGENTS.md` line in `CLAUDE.md` if you don't want it, `devbook.lock.json`, and the hooks and permission rules it added to `.claude/settings.json`. Uninstall the skills and plugins listed in the lock file with the same tool that installed them: `claude plugin uninstall <name> --scope project`, or `gh skill` for skills in `.agents/skills/`.
