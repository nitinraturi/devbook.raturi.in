The [setup prompt](/#setup) does all of this for you. The steps below show the same setup done by hand. New to instruction files? Read [How Devbook works](/start-here/how-it-works/) first.

**You need:** a git repository, and an assistant that reads `AGENTS.md` or `CLAUDE.md`, such as Claude Code or GitHub Copilot in agent mode, with file editing and terminal access turned on.

## 1. Choose how to add Devbook

Both methods put the files in `.devbook/`, so the rest of the setup is the same. Pick a tab.

<Tabs syncKey="method">
<TabItem label="Submodule (tracks updates)">

Follows `main`. You update with one git command, and every update shows up as a reviewable change.

```sh
git submodule add -b main https://github.com/nitinraturi/devbook.raturi.in .devbook
```

</TabItem>
<TabItem label="Copy (plain files)">

Downloads plain files that you commit. It works offline afterwards, needs no submodule support from tools or cloud agents, and only changes when you download again.

```sh
rm -rf .devbook && mkdir -p .devbook && curl -fsSL https://codeload.github.com/nitinraturi/devbook.raturi.in/tar.gz/main | tar -xz --strip-components=1 -C .devbook devbook.raturi.in-main/instructions devbook.raturi.in-main/stacks devbook.raturi.in-main/templates devbook.raturi.in-main/LICENSE-CC-BY-4.0
```

On Windows PowerShell, which has no `rm -rf` or `mkdir -p`, use the `curl.exe` and `tar.exe` that ship with Windows 10 and later:

```powershell
Remove-Item -Recurse -Force .devbook -ErrorAction SilentlyContinue; New-Item -ItemType Directory -Path .devbook | Out-Null; curl.exe -fsSL https://codeload.github.com/nitinraturi/devbook.raturi.in/tar.gz/main -o devbook.tar.gz; tar.exe -xzf devbook.tar.gz --strip-components=1 -C .devbook devbook.raturi.in-main/instructions devbook.raturi.in-main/stacks devbook.raturi.in-main/templates devbook.raturi.in-main/LICENSE-CC-BY-4.0; Remove-Item devbook.tar.gz
```

Without a terminal, download the [ZIP of `main`](https://github.com/nitinraturi/devbook.raturi.in/archive/refs/heads/main.zip). Copy its `instructions/`, `stacks/` and `templates/` folders and its `LICENSE-CC-BY-4.0` file into `.devbook/`.

</TabItem>
</Tabs>

## 2. Connect your assistants

<Steps>

1. Create `AGENTS.md` at the repository root and fill in the Project section with your real commands, layout and rules. In the Devbook section, keep only the lines that apply: core, security and testing always, then the others from [the table of when to load each file](/start-here/how-it-works/#mandatory-and-optional-files), plus one stack note for each technology you use.

   <Code code={agentsTemplate} lang="md" title="AGENTS.md" />

2. Create `CLAUDE.md` containing one line:

   ```md
   @AGENTS.md
   ```

3. Create `.github/copilot-instructions.md`:

   <Code code={copilotTemplate} lang="md" title=".github/copilot-instructions.md" />

4. Commit `.devbook` (plus `.gitmodules` for a submodule), `AGENTS.md`, `CLAUDE.md` and `.github/copilot-instructions.md`, then start a new chat.

</Steps>

## How the instructions load

Claude Code expands the `@` lines; Copilot and other assistants read `AGENTS.md` and open the listed files. Write `@` paths as plain text, because an `@` path inside backticks is not imported. [How Devbook works](/start-here/how-it-works/#how-each-assistant-loads-the-rules) explains each assistant and which rule wins.

<Aside type="caution" title="Cloud agents and submodules">
Hosted agents only see a submodule's files if their checkout includes submodules. If an agent says the files are missing, add `git submodule update --init` to its setup steps. For the Copilot coding agent, those steps live in `.github/workflows/copilot-setup-steps.yml`. You can also switch to the Copy method, whose files are in the repository itself.
</Aside>

## Update, clone or remove

<Tabs syncKey="method">
<TabItem label="Submodule (tracks updates)">

```sh
git submodule update --remote .devbook       # pull the latest Devbook, then commit the change
git clone --recurse-submodules <your-repo>   # clone a project that uses Devbook
git submodule update --init                  # fetch .devbook in an existing clone
git rm .devbook                              # remove; then delete the @ lines from AGENTS.md
```

</TabItem>
<TabItem label="Copy (plain files)">

Run the download command again, then review `git diff .devbook` and commit. The command replaces the whole folder, so files removed upstream are removed in your copy too. To remove Devbook, delete `.devbook/` and the `@` lines from `AGENTS.md`.

To switch from Copy to Submodule, delete `.devbook/`, commit the deletion, then run the submodule command.

</TabItem>
</Tabs>

Devbook has no version pins. Either way, your repository records exactly which Devbook text it uses, so an update is a normal reviewable change. Review it before you commit: these files steer your assistant, so treat an update like a dependency upgrade.
